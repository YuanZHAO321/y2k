这是人类文明的第二个千年,也是太阳的第二十个银河年。

而在本科纪元里,此刻是第一年的最后一夜——时钟即将从 **01** 跳到 **02**。

在旧纪元里,时间以「周」计,一共 **112** 个;记忆以「词」计,一共 **1,200,220** 个。而负责存储这一切的系统——一颗人脑——和 1999 年所有的老系统一样:**只用两位数记年,并且会遗忘。**

纪元切换的午夜迟早要来。没有打过补丁的系统,会在那一夜把 99 进位成 00——大一清零,知识溢出,记忆回卷到出厂设置。

1999 年的工程师们把这个隐患叫做**千年虫**。他们的对策是:在午夜到来之前,把每一行旧代码翻出来,逐行重读、重写、归档、验收。

我们如法炮制。

```
> 1999-12-31 23:59:50  BOOT PATCH SEQUENCE ...............  OK
```

## 00 · 系统公告

本仓库是**大一地球科学(Earth Sciences)全年知识的完整归档**:13 门子课程、112 个教学周、约 120 万词的课件、讲义与课堂录音转写,由一支 AI Agent 流水线逐周全文精读,重写为 **125 份中文笔记**——112 份周笔记、12 份课程总纲、1 份野外实习笔记。

设计目标只有一个:**复习时,可以不再翻任何原材料。**

## 01 · 补丁使用说明

1. **按周修复**:每门课的 `Notes/Week NN.md` 是基石——逐周详尽笔记(约 1500–3000 字),覆盖 slides、讲义与课堂录音的全部内容。
2. **重建全局**:每门课根目录下的 `Course Notes.md` 是课程总纲——全课主线、各周关系、核心结论与重点难点,配合周笔记使用,不重复细节。
3. **先读勘误**:千年虫不只藏在年份里。原材料中的知识性错误、数值错误、语音识别错词、PDF 转换丢失,已在各课程总纲的**勘误表**中逐条捕获,全年累计 200+ 条——复习前先过一遍,避免把 bug 复习进脑子。
4. **不确定学习顺序?** 看 [`Freshman/order.md`](Freshman/order.md):13 门课的推荐顺序,以及每门课在整个知识系统中的定位理由。

## 04 · 补丁规格

**语言**:中文为主;专业术语、定义、公式保留英文原文——术语不做有损压缩。

**周笔记**(每份约 1500–3000 字)固定七段结构:

1. **本周主题** — 一两句话定位本周在全课中的位置
2. **核心概念** — 解释完整,不只列名词
3. **公式与图表** — 公式保留原文并解释各项含义,关键图表用文字描述
4. **课堂补充** — transcript 中 slides 没有的口头讲解与强调重点
5. **Practical 要点** — 目的、方法步骤、关键结论
6. **易错点 / 重点难点**
7. **本周术语表** — 中英对照

**课程总纲**在此之上给出全课知识体系,并视课程情况附:勘误表、考试信息汇总、语法/公式速查、原材料转换丢失内容清单等。

## 05 · 修复工程

这次大修由一个主控 Agent 调度数十个子 Agent 流水线完成——和 1999 年那次一样,靠的不是魔法,是纪律:

- **逐周全文精读**:每个教学周派 1 个子 Agent,通读该周全部材料**全文**——slides、讲义与课堂录音转写(transcript)同等地位,不跳读;同周的 Lecture 与 Practical 由同一个 Agent 配对处理。
- **先勘误后成文**:子 Agent 不盲信原材料——课件排错、周号错位、语音识别错词、PDF→md 转换丢失,都会核查并写进笔记与勘误表。
- **主控与内容隔离**:主控只做调度、追踪与 git 操作,不读任何材料与笔记正文,保证主对话不被百万词级的内容淹没。
- **反事实重放**:因材料出错而重做时,以「假如一开始拿到的就是正确材料」为准绳重建,严禁下游信息倒灌。
- **逐门验收**:每完成一门课即 commit + push 并暂停,等用户确认后再进入下一门——没有哪次跨年,是不做验收就敢切换系统的。

完整规则见 [`PLAN.md`](PLAN.md);材料清单、词数统计与配对裁定见 [`Freshman/manifest.md`](Freshman/manifest.md)。
